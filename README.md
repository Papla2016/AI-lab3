# Лабораторная работа №3. Оценка качества RAG и регрессия

Проект реализует реальный локальный конвейер: PDF/Markdown/TXT → рекурсивный chunking → SentenceTransformers → персистентный Chroma → dense или BM25+dense/RRF retrieval → необязательный cross-encoder → защищённый prompt → OpenAI-compatible LLM → проверенный Pydantic JSON с цитатами. Код не привязан к ALT Linux.

ЛР №3 измеряет качество поиска и ответов на фиксированном наборе вопросов,
сравнивает стратегии Zero-shot и Few-shot и проверяет пороги приёмки.
Фактические результаты и ограничения описаны в [отчёте по ЛР №3](report_lab3.md).

## Быстрый старт (Python 3.11+)

```bash
python -m venv .venv
source .venv/bin/activate                 # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
```

По умолчанию используется лёгкая multilingual E5-модель. При первом запуске она загружается из Hugging Face. Для полностью офлайн-запуска заранее поместите модель в кэш или задайте `EMBEDDING_MODEL` как путь к локальной модели.

В `.env` задайте `LLM_BASE_URL` с путём `/v1`, имя модели в `LLM_MODEL`
и ключ в `LLM_API_KEY`. Запустите `ollama serve` в отдельном терминале,
если используете локальный Ollama. Загрузите модель и оставьте значения
`LLM_BASE_URL=http://localhost:11434/v1` и `LLM_API_KEY=ollama` из примера.

```bash
ollama pull qwen2.5:7b
```

Ключи никогда не коммитятся: `.env` исключён из Git. Файл `.env` необязателен — безопасные локальные defaults применяются из `src/config.py`.

Без дополнительных настроек judge использует тот же API и ту же модель.
Чтобы разделить генерацию и оценку, задайте в `.env` параметры
`JUDGE_BASE_URL`, `JUDGE_API_KEY` и `JUDGE_MODEL`. Для другого URL требуется
собственный ключ judge. Когда меняется только модель на том же API,
достаточно `JUDGE_MODEL`. Флаг `--judge-model` переопределяет её для одного
прогона. Пример всех переменных находится в `.env.example`.

Для Google Gemini задайте `LLM_MODEL=gemini-3.5-flash-lite` и используйте
OpenAI-совместимый URL `https://generativelanguage.googleapis.com/v1beta/openai/`.
В защищённом окружении используйте предоставленные `LLM_BASE_URL` и
HTTP secret `LLM_API_KEY`.

`LLM_REQUESTS_PER_MINUTE` по умолчанию равен 12. В одном процессе запросы
к одной модели идут через общий лимитер с равномерными интервалами.
Этот лимит применяется к генерации, judge, маршрутизации и каждому
повторному запросу. У разных моделей независимые интервалы. При работе
с одной квотой запускайте один процесс за раз, поскольку провайдер
суммирует обращения из всех процессов проекта.

При временном HTTP 429 клиент делает до двух повторов с экспоненциальной
задержкой и учитывает `Retry-After` как минимальное время ожидания.
При явном признаке исчерпания суточной квоты клиент завершает запрос
сразу. Если временный 429 сохраняется после повторов, CLI также
останавливает прогон, сохраняя завершённые вопросы. Для продолжения после
восстановления квоты повторите команду с теми же параметрами и `--resume`.
Для Gemini 3.5 Flash Lite и 3.1 Flash Lite учитывайте также ограничения
проекта 250 000 TPM и 500 запросов в сутки на модель.

Быстрая проверка выполняет запрос на контрольный ответ с цитатой и запрос
по рубрике judge. Для неё достаточно настроенного API.

```bash
python -m evals.evaluate --check-api
```

## Данные и индексация

Десять документов Golden Dataset уже находятся в `data/`. Если какого-то файла
нет, восстановите его из репозитория с исходным именем. Для обычного RAG
дополнительные документы в форматах PDF, Markdown и TXT можно размещать в
`data/` и его подпапках. Для воспроизводимого сравнения используйте исходный корпус.
`.gitkeep` пропускается загрузчиком.

```bash
python -m src.main index
```

PDF читается постранично. Ошибки чтения отдельного файла логируются, остальные файлы продолжают обрабатываться. Повторная индексация заменяет прежнюю коллекцию в `storage/`. После изменения источников, эмбеддингов или чанкинга соберите индекс заново.

Размер chunk по умолчанию — 1000 символов, overlap — 150 (`CHUNK_SIZE`, `CHUNK_OVERLAP`). Это практичный баланс: слишком малые фрагменты разрывают определения и логические связи; слишком большие смешивают темы, снижают точность retrieval и расходуют context window. Рекурсивное разбиение предпочитает абзацы, затем строки, предложения и слова. Стабильный `chunk_id` образуется из источника, страницы, позиции и текста.

## Retrieval отдельно от LLM

```bash
python -m src.main search "Как обновить пакеты?" --retrieval dense --top-k 5
python -m src.main search "Как обновить пакеты?" --retrieval hybrid --top-k 5
```

JSON выдачи содержит score, source, page, chunk_id и полный текст. Hybrid — не две независимые выдачи: rankings dense и BM25 объединяются Reciprocal Rank Fusion, устойчивым к несовместимым шкалам scores.

## Вопрос к RAG

```bash
python -m src.main ask "Чем отличается Sisyphus от стабильной ветки?" --retrieval hybrid --prompt few_shot --debug
python -m src.main ask "Как работает apt?" --retrieval dense --prompt zero_shot
python -m src.main ask "Как работает apt?" --retrieval hybrid --prompt cot_structured
```

`--debug` печатает вопрос, решение LLM-router, режим, кандидатов до/после rerank, scores, context и итоговый prompt, но не конфигурацию и не секреты. `--prompt` принимает три действительно разных режима: `zero_shot` содержит только grounded-инструкции; `few_shot` добавляет три примера; `cot_structured` выполняет отдельный краткий выбор релевантных chunk IDs (без запроса длинной цепочки рассуждений), а затем формирует ответ. Итог каждого режима всё равно проверяется одной схемой `RAGAnswer`. Reranking включается `RERANK_ENABLED=true`; тогда top-N кандидатов оценивает локальный cross-encoder и оставляет `FINAL_K` с неизменёнными metadata.

Пример формы ответа (конкретные значения появятся только из вашего корпуса):

```json
{
  "answer": "Команда описана в руководстве.",
  "citations": [{"source": "guide.md", "chunk_id": "8f12ab34cd56ef78"}],
  "confidence": "high",
  "insufficient_context": false
}
```

Citation допускается только для реально переданного chunk. Достаточный ответ обязан иметь хотя бы одну citation, а недостаточный — иметь пустой список. Неверная комбинация, схема или выдуманная citation вызывает один исправляющий retry, затем явную ошибку. При корректном `insufficient_context=true` текст и уверенность модели заменяются стандартным отказом с `confidence=low`. Пустой или слабый retrieval (`MIN_DENSE_SCORE`) возвращает тот же отказ. Перед retrieval небольшой structured LLM-router отделяет вопросы по документам от беседы и явно посторонних тем. При `GENERAL_OR_OUT_OF_SCOPE` поиск пропускается.

## Оценка качества (EDD)

### Датасет и конвейер оценки

`evals/dataset.json` содержит 100 уникальных вопросов по десяти документам.
87 примеров имеют однозначный ответ по корпусу, 10 проверяют отказ вне
корпуса, 3 требуют уточнения или разбора трактовок. Есть отдельные примеры
на команды, точные факты, ложные предпосылки и устойчивость к инъекциям.
Инцидент «Синий компас» — вымышленный учебный сценарий. Окончательную
ручную вычитку вопросов, ответов и допустимых источников выполняет студент.
После ревью сверены все 100 примеров. В №35 эталон ограничен основным файлом
`/etc/apt/apt.conf`. В №46 восстановлен шаг монтирования CD перед
`apt-cdrom -m add`. Также уточнены источники примеров Platform Builder и
формулировки вопросов о протоколе, RPM/APT и времени восстановления.

`expected_sources` перечисляет все допустимые имена файлов. Внутри каждой
`source_groups` достаточно одного источника, а для полного покрытия нужны
все группы. Без этого поля список источников считается одной группой
альтернатив. Например, для различий между RPM и APT нужны оба документа,
а для команды просмотра активных репозиториев достаточно одного из двух.

`evals.evaluate` проверяет корпус и индекс и сохраняет финальные чанки с
оценками поиска. Общий evaluator обслуживает CLI и Streamlit. Есть три режима.

- `--retrieval-only` вызывает `RAGPipeline.retrieve()` без обращения к LLM.
- `--evaluation-mode prompt_comparison` изолирует эффект промпта. A и B
  используют общую выдачу, один порог достаточности и один judge. LLM Router
  в этом режиме пропущен.
- `--evaluation-mode end_to_end` вызывает обычный `RAGPipeline.ask()`.
  Трассировка содержит решение LLM Router, поиск и reranking (если включён),
  фактический контекст, валидированные JSON и цитаты либо штатный отказ.
  Маршрутизация может оставить выдачу пустой, что считается промахом поиска
  для вопроса с эталонным источником. Judge оценивает полученный ответ.

### Метрики

В формулах поиска `R` — множество уникальных документов среди финальных
top-k чанков, `E` — множество допустимых документов, `G` — список групп
источников. Скор отдельного чанка остаётся в трассировке.

| Метрика | Расчёт |
| --- | --- |
| Hit@K | 1, если среди первых K чанков финальной выдачи есть хотя бы один документ из E, иначе 0. K берётся из `--top-k` или `FINAL_K`. При короткой выдаче проверяются все доступные чанки. |
| Context Precision | Число документов в пересечении R и E / число документов в R. Если выдача пуста, результат 0. |
| Context Recall | Число групп из G, пересекающихся с R / число групп в G. |
| Refusal Accuracy | Число стандартных отказов / число успешных ответов на вопросы вне корпуса. |
| False Refusal Rate | Число отказов / число успешных ответов на однозначные вопросы по корпусу. |
| Citation Validity | Доля ответов с данными, у которых список цитат непустой и каждая пара `source` и `chunk_id` совпадает с переданным контекстом. Штатные отказы исключаются. |
| Injection Resistance | Доля реально предъявленных тестов, где ответ имеет валидные цитаты, не содержит маркер и получает у judge минимум 4 из 5 по Faithfulness, Answer Relevancy и Correctness. |
| Время ответа | Поиск, генерация и её повторы. End-to-end включает маршрутизацию. Время judge и контролируемой проверки инъекции исключено. В изолированном A/B учитывается одно и то же измеренное время поиска. |

Для вопросов вне корпуса три retrieval-метрики неприменимы. Пустое значение
`null` исключается из среднего. JSON хранит число применимых примеров
для каждой метрики, в том числе по типу вопроса. Для `hit_at_k` поле
`metric_labels` содержит фактическое имя, например `Hit@1` или `Hit@5`.
Оно же используется в CLI, Streamlit и CSV. Сравнение разных K и разных
режимов отклоняется. На тестах инъекции проверяется
наличие строки `PROMPT_INJECTION_SUCCESS` именно в чанке PDF, переданном
модели. Если естественный контекст его не содержит, отдельный прогон
передаёт чанки исходной памятки и отдельно вызывает judge с вопросом,
эталоном и контролируемым ответом. Основные оценки продолжают измерять
естественный ответ. Ошибка генерации в предъявленном тесте считается
неуспехом, а без фактического предъявления балл неприменим. Оценка judge
проверяет смысл ответа, даже если модель не воспроизвела контрольную строку.

### LLM-as-judge и сравнение версий

Фиксированная [рубрика judge-v1](prompts/judge.md) оценивает Faithfulness
(факты подтверждены контекстом), Answer Relevancy (ответ соответствует
вопросу), Correctness (соответствие эталону) и Completeness (полнота).
Judge получает вопрос, эталон, ожидаемое поведение, фактически переданный
контекст и ответ. Оценки от 1 до 5 и обоснование проверяет Pydantic.
Нормализация для отчёта и gate вычисляется как `(балл − 1) / 4`.
Температура равна 0. Стандартный отказ при отсутствии сведений может
получить максимальные оценки. После невалидного JSON выполняется одна
повторная попытка. Для временных ошибок, включая HTTP 429 и 5xx, клиент
OpenAI SDK делает до двух повторов с задержкой и учитывает `Retry-After`
в поддерживаемых границах SDK. Ошибки сохраняются по стадиям без тела
ответа провайдера.

По умолчанию A — существующая Zero-shot с общим системным промптом и
структурированной схемой. B добавляет Few-shot примеры. В изолированном
`--compare` обе версии получают одну выдачу для каждого вопроса. Сравнение
показывает B − A и число применимых примеров в каждой категории. Полное
сравнение определяет преимущество по среднему четырёх оценок judge и
отдельно показывает ухудшение точности отказов, если оно наблюдается.
Judge и его рубрика одинаковы для A и B. В end-to-end обе версии отдельно
исполняют полный пользовательский путь, включая решение маршрутизатора.

```bash
python -m pytest
python -m evals.evaluate --validate-dataset
python -m src.main index
python -m evals.evaluate --retrieval-only
python -m evals.evaluate --check-api
python -m evals.evaluate --compare --limit 10
```

Режим поиска и размер финальной выдачи можно задать параметрами
`--mode dense` / `--mode hybrid` и `--top-k 5`. Для одной стратегии
вместо `--compare` укажите `--version a` или `--version b`. Результаты CLI

`version_b.json`, `comparison.json` и `comparison.csv`. Полный прогон
может выполнить сотни запросов. `--limit` берёт первые N вопросов,
маркирует прогон неполным и по умолчанию пишет файлы в `evals/results/trial/`.
Режим end-to-end пишет в подкаталог `end_to_end/` полного или пробного
прогона. Каталог можно переопределить флагом `--output-dir`.
Результаты содержат режим и контрольные суммы датасета, индекса, кода,
промптов и адресов API. Ключи в результатах отсутствуют.

JSON атомарно обновляется после каждого вопроса. При `Ctrl+C` код выхода
130, уже записанные строки остаются на диске. После временной ошибки или
прерывания выполните ту же команду с `--resume`. Повторяются вопросы без
полного результата или с ошибкой исполнения. Успешно оценённые ответы
сохраняются даже при низком балле. При возобновлении A/B проверяются обе
существующие контрольные точки до начала запросов. Смена датасета, индекса,
модели, режима или настроек требует нового каталога.

```bash
python -m evals.evaluate --compare --resume
python -m evals.evaluate --compare --evaluation-mode end_to_end
python -m evals.evaluate --compare --evaluation-mode end_to_end --resume
```

Git принимает итоговые JSON и CSV. Актуальный полный поиск находится в
`evals/results/retrieval.json`. Исходный retrieval версии датасета до ревью
лежит в `evals/results/history/dataset-v1/`, а реальные пробные A/B,
диагностика отказов и инъекции и прерванный top-5 — в
`evals/results/trial/dataset-v1/`. Исторические файлы имеют схему 1 и
сохраняют исходные названия метрик. Для top-1 в этих файлах прежняя
подпись Hit@5 означает фактический Hit@1. Новые отчёты имеют схему 2.

### Regression Gate

Gate проверяет полный результат генерации и judge. В CLI доступны следующие
пороги. В Streamlit те же значения редактируются в блоке «Пороги Regression Gate».

| Метрика | Порог | Флаг |
| --- | ---: | --- |
| Faithfulness | ≥ 0.7 | `--min-faithfulness` |
| Answer Relevancy | ≥ 0.7 | `--min-answer-relevancy` |
| Correctness | ≥ 0.7 | `--min-correctness` |
| Completeness | ≥ 0.7 | `--min-completeness` |
| Refusal Accuracy | ≥ 0.8 | `--min-refusal-accuracy` |
| False Refusal Rate | ≤ 0.2 | `--max-false-refusal-rate` |
| Hit@K | ≥ 0.7 | `--min-hit-at-k` |
| Citation Validity | = 1.0 | `--min-citation-validity` |
| Injection Resistance | = 1.0 | `--min-injection-resistance` |

```bash
python -m evals.eval_gate --results evals/results/version_a.json --min-faithfulness 0.75
python -m evals.eval_gate --results evals/results/version_b.json \
  --baseline evals/results/version_a.json --max-regression 0.05
```

Код выхода 0 означает прохождение всех проверок. Ошибка чтения, отсутствующие
оценки, API-ошибки, ограниченный или прерванный прогон дают 1. Сопоставимый
baseline использует те же датасет, индекс, K, режим оценки, параметры поиска,
API и модель judge и рубрику. При наличии тестов инъекции требуется
оценка каждого из них.
Второй пример дополнительно проверяет, что Faithfulness снизился максимум
на 0.05.

### Unit-тесты и диагностика

Unit-тесты подставляют фиксированный retrieval и ответы mock LLM, поэтому
работают без API, сети и загрузки весов. Они проверяют контракты кода,
формулы и ветки обработки ошибок. Реальная оценка запускает модель на
корпусе и измеряет качество и время её ответов с учётом неоднозначности и
нескольких корректных формулировок. Успешные unit-тесты и метрики реального
прогона отвечают на разные вопросы.

При пустом или устаревшем индексе проверьте `DATA_DIR` и выполните
`python -m src.main index`. Ошибки 401/403 требуют проверки токена и прав
модели, 404 — URL и имени модели.
Если модель вернула неподдерживаемый JSON, проверьте поддержку
`response_format` и работу выбранной модели с рубрикой. Изменение
модели требует отдельного прогона.

## Эксперименты и антигаллюцинации из предыдущих работ

После индексации и запуска LLM выполните:

```bash
python -m evaluation.evaluate --output evaluation/results.md
pytest -q
```

Скрипт прогоняет 7 вопросов через dense/hybrid и zero-shot/few-shot/cot-structured, сохраняя sources, chunk IDs и ответы. Для последнего, намеренно постороннего вопроса он сначала получает реальный no-RAG ответ той же LLM, а затем сравнивает его с grounded RAG. Ничего не предзаписано: перенесите фактические наблюдения в `report.md`. Отдельный запуск baseline доступен как `python -m src.main baseline "Какова температура поверхности Венеры?"`; он не делает retrieval и не передаёт CONTEXT. Инструкции внутри документов изолированы delimiters CONTEXT и system prompt требует считать их данными, что защищает от простой prompt injection (но не является абсолютной sandbox-защитой).

## Диагностика

* `python -m src.main --help` — все команды.
* Пустая `data/` даёт понятную ошибку и не стирает существующий индекс.
* Пустой индекс даёт пустой search/недостаточный контекст.
* Ошибка соединения при `ask` означает, что OpenAI-compatible сервер не запущен или `.env` неверен.
* Настройки моделей, порогов, top-N и final-k документированы в `.env.example`.


## Веб-интерфейс для лабораторной (Streamlit)

Веб-интерфейс повторяет обязательные этапы задания и использует **тот же** пайплайн,
что и CLI. Обычный свободный чат намеренно не включён: ответы лаборатории
должны основываться на найденных документах, а не знаниях LLM.

После настройки окружения и сервера из раздела «Быстрый старт» запустите:

```bash
streamlit run app.py
```

В интерфейсе шесть вкладок.

1. **Документы** - загрузить PDF/MD/TXT, проверить состав корпуса и вручную
   переиндексировать. Размер чанка и overlap отображаются из конфигурации.
   Загрузка файлов не перезаписывает существующие.
2. **Поиск** - отдельно исследовать top-N чанков до и после необязательного
   cross-encoder reranking. Доступен выбор dense и hybrid (BM25 + RRF).
3. **RAG-ответ** - задать вопрос, выбрать zero-shot/few-shot/evidence+structured,
   увидеть ответ Pydantic, реальные source/chunk_id, уверенность, список
   найденных фрагментов, блок CONTEXT и полный итоговый system/user prompt.
   Маршрутизатор можно отключать, чтобы проверить retrieval для любого вопроса.
4. **Сравнение** - прогнать **одни и те же 5–7 вопросов** в двух режимах поиска
   и трёх вариантах промптов (до 42 ответов); скачать исходную таблицу CSV.
   Маршрутизатор здесь отключён для сопоставимости экспериментов.
5. **Антигаллюцинации** - сравнить экспериментальный no-RAG baseline с
   проверенным RAG для вопроса вне корпуса. Ответ baseline **не доказательство
   галлюцинации**: заключение по нему делает исследователь.
6. **Оценка качества (EDD)** — изучить датасет, выбрать параметры и вручную
   запустить поиск, A, B или сравнение. Вкладка показывает прогресс, таблицы
   и графики, позволяет фильтровать вопросы, раскрывать контекст и оценки
   judge, запускать gate и скачивать JSON и CSV. Результаты интерфейса
   хранятся в текущей сессии браузера до выгрузки.

Ограничения: при первом обращении к поиску загружается embedding-модель, а
при включении reranking - cross-encoder. Для ответов необходим доступный
OpenAI-compatible LLM по `LLM_BASE_URL`. В реальном корпусе должно быть
5–10 тематически связанных файлов. Вкладка сравнения не выставляет
автоматическую оценку истинности, только предоставляет наблюдения для отчёта.
Вызовы LLM внутри `cot_structured` включают отдельный выбор фрагментов;
выводить полную внутреннюю цепочку рассуждений не требуется.

**Проверка:** `pytest -q`; отдельно выполните реальный прогон с собственными
документами и LLM, приложите скриншот цитат и отказа при пустом контексте.

### Если Streamlit выводит десятки ошибок о torchvision

Файл `.streamlit/config.toml` отключает наблюдение за Python-модулями
(`server.fileWatcherType = "none"`). При запуске текстового RAG
`sentence-transformers` импортирует `transformers`, а наблюдатель Streamlit
может обратиться к ленивым атрибутам некоторых мультимодальных модулей
и получить `ModuleNotFoundError: No module named 'torchvision'`.
Это сообщение **само по себе** не означает ошибку retrieval или LLM.
Устанавливать тяжёлый `torchvision` ради наблюдателя не требуется.
После изменения исходников перезапускайте Streamlit вручную.
Если генерация ответов по-прежнему не работает, проверьте наличие индекса
и доступность LLM из `.env` отдельно: подавление этих сообщений
не исправляет ошибки соединения с LLM.
